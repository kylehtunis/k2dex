# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Research code applying complexity-science / distributional-semantics methods to competitive Pokemon (VGC) team-composition data. Three inverse Ising pairwise-MaxEnt models fit `(J, h)` to different data:

- **Gaussian model** — precision-matrix approximation on Smogon chaos JSON. Lives in notebooks only.
- **Species model** — pseudo-likelihood (PL) fit on Limitless tournament rosters, species-only vocab.
- **Species+Item model** — PL fit on `(species, item)` pair features from the same Limitless data.

Webapp: a static React/TS site (`web/`, the public surface on GitHub Pages). It surfaces precomputed models via a manifest-driven picker with four tool surfaces: `/completer`, `/analysis`, `/meta`, and `/pokemon` (a usage-ranked species index plus one prerendered page per species), plus an `/articles` section whose first article is the `/science` explainer. User-facing terminology: `J` = "Coupling Strength", `h` = "Bias", `ΣJ` = "Coherence", `E` = "Score" (sign-flipped), `anchor_strength` = "Anchor Strength" (the completer's anchor-field tilt alpha). `field_weight` is fixed at 1 (no UI knob). (A Streamlit research app formerly lived at `scripts/app.py`; it and its HTML/CSS helpers (`k2dex/styles.py`, the sprite/HTML builders in `rendering_html.py`) have been removed. `rendering_html.py` is now trimmed to `species_to_slug`, which stays only because it is parity-gated against the webapp's `speciesToSlug` port.)

## Key module notes

Read the code for full APIs. These are the non-obvious parts:

- **`models.py`** — `fit_pl_ising` uses `scipy.optimize.minimize` (L-BFGS-B), not sklearn. Degenerate spins (< 2 units weighted mass) are skipped and fall back to prior or zero. Prior support enables cross-regulation warm-starting. `fit_boltzmann_ising` is the alternative **moment-matching** fit (constrained-MaxEnt / Boltzmann learning): warm-starts from the PL fit, then ascends the regularized log-likelihood with model moments from a persistent batched swap-chain bank (PCD). `empirical_moments(X, w)` returns the weighted 1-pt/2-pt targets. For the species+item ensemble it samples the PCD bank with the **Potts move kernel** (`potts_moves=True`, the default when `species_of` is given): a random-scan mixture of a Metropolized-Gibbs **species swap** (accept on the local free-energy ratio `Z_B/Z_A`, then draw the full state — all tracks — from the exact conditional) and a **per-track Gibbs reroll** (`_potts_species_swap_sweep` / `_potts_track_reroll_sweep` / `_advance_bank_potts`, built on `_build_site_tables` + `_build_feat_lookup` + `_site_conditional`). This treats species selection and each attribute track as separate moves; the species-only ensemble keeps the atomic `_batched_swap_sweep` (the q=2 reference the Potts kernel degenerates to). Both target the same constrained Gibbs measure. Within-species couplings are frozen at 0 and dropped from the fit mask (same-species states never co-occur, so their coupling is unconstrained). The kernel is **true multi-track**: `_site_conditional` takes an optional per-track `pin_values` mask (-1 = free) restricting candidate states to those matching every pinned track — a species swap passes all-free (joint draw over all tracks); a per-track reroll of track `t` pins every other track to the slot's current values (Gibbs on `P(v_t | v_{-t}, team)`) and writes only column `t`. Item (the cross-slot-unique track, from `item_of`) still drives item-exclusion; ability is a non-unique track (members may share it). The Potts PCD bank is **factored**: `team_sites` (n_temps, n_chains, team_size) holds site (species) ids and `team_values` (…, n_tracks) the per-track **value ids**; `feat_lookup[site, v_0, v_1, …]` (an (n_tracks+1)-D table from `_build_feat_lookup`) rebuilds flat feature indices via `_bank_flat_indices` for energy/moment/replica-exchange code. A conditional draws a candidate **column** (a full state); its per-track value ids are read off the site table's `sp_track_vid` and written into `team_values` (all tracks on a swap, one track on a reroll). Reroll-track selection is weighted by `POTTS_TRACK_REROLL_WEIGHTS` (item ≫ ability); `p_reroll` defaults to `POTTS_REROLL_PROB`. `fit_boltzmann_ising` takes the full track structure via `track_values`/`track_names` (single item track when omitted, the pre-ability behavior); loaders pass the item+ability tracks. Currently exercised at n_tracks=2 (item + ability).
- **`sampling.py`** — `swap_mcmc` / `anneal_mcmc` use the atomic `_local_swap_step`, but `parallel_tempered_mcmc` now runs the **universal multi-track Potts move kernel** (per-chain `build_site_tables` / `site_conditional` / `_potts_species_swap_step` / `_potts_track_reroll_step`): each sweep is a species-swap (joint draw over all tracks), or — when the model has tracks — with probability `p_reroll` (default 0.5) a **per-track reroll**. `build_site_tables(species_of, track_values_of, V)` groups features by species and builds both the sparse `item_id` (unique/item track, null → −1, drives item-exclusion) and the dense `track_vid` (V, n_tracks) per-track value ids (null is a real id, so a track can be pinned to an exact value); mirrors `models._build_site_tables`' `sp_track_vid`. `site_conditional` gained an optional per-track `pin_values` (−1 = free) restricting candidates to states matching every pinned track — a species-swap passes all-free (joint), a reroll of track `t` pins every other track to the slot's current values (Gibbs on `P(v_t | v_{-t}, team)`). Reroll-track selection is weighted (`_pick_track` ∝ per-track weights; TS builds them from `POTTS_TRACK_REROLL_WEIGHTS`). **Python PT is item-track-only in practice** (training/test surface — `estimate_moments`, anchor tests); genuine multi-track sampling runs in the TS kernel (the webapp path). Species-only (no tracks) degenerates to the atomic swap. This is the per-chain mirror of `models.py`'s batched training kernel and the 1:1 counterpart of `web/src/sampler/potts.ts`. `build_constraint_sets`/`swap_violates_uniqueness`/`initialize_state` still gate the atomic samplers. **Mirrored 1:1 in `web/src/sampler/`**, gated by `tests/test_parity.py` (which carries a synthetic **2-track** `model2` exercising `track_vid` + `pin_values`). `estimate_moments` (free PT generation → 1-pt/2-pt model moments) is **training-only Python — NOT ported to TS, no parity row** (the webapp consumes the resulting `(J,h)`, never the training loop). Same for `fit_boltzmann_ising` and the `_batched_*` / `_potts_*_sweep` / `_advance_bank_potts` batched training helpers in `models.py` (no TS/parity obligation). The two **deterministic** per-chain Potts helpers `sampling.build_site_tables` / `sampling.site_conditional` DO have parity rows (see the duplicated-code table); the stochastic per-chain steps (species-swap + per-track reroll) are JS-smoke-tested only.
- **`loaders.py`** — `build_species_model()` / `build_species_item_model()` accept `prior_regulation`/`intercept_prior_weight` for warm-start. `team_weights` computes `w = exp(-dt/tau) * m^[in-person]`, normalized to mean 1. `build_species_item_model` forms `(species, item, ability)` **triples** (the vocab-cutoff key is the full triple), normalizing a missing item (Python `None`) to the string `"None"` so an itemless build is an ordinary Potts state (subject to item uniqueness) and split duplicates merge; ability is always a real string (ingest drops abilityless members). Both builders return a **`SpeciesModel` NamedTuple** whose `track_specs` (`[]` for species-only, `[ITEM_TRACK, ABILITY_TRACK]`) + per-feature `track_values_of` generalize the old flat `item_of`; `item_of`/`ability_of` are derived `@property` views (item = track 0, ability = track 1), so callers that only need the item (the current fit's uniqueness lookup) are unchanged. The fit still takes only `species_of` + the item view — ability is not a uniqueness dimension, it just makes more distinct features. `format_pair(species, item)` stays byte-stable (parity); `format_triple(species, item, ability)` → `"Species @ Item (Ability)"`, itemless (`item` `"None"`/None) drops `@ Item` → `"Species (Ability)"` (parity twin `render/format.ts:formatTriple`). Precompute reads the model's `track_specs`/`track_values_of` to emit the schema tracks.
- **Artifact schema v4 (factored `sites` + `tracks`, multi-track)** — `meta.json` stores `sites: string[]` (distinct species, vocab order), `site_of: number[]` (per-feature site index), `tracks: {name, cardinality, crossSlotUnique, withinSlotUnique}[]` (attribute definitions; `[]` for species-only, `[{item}, {ability}]` for the standard species+item+ability build), and `track_values: (string|null)[][]` (per-feature per-track values, in track order). Track fields: `cardinality` = values a member holds on this track (1 for item/ability; a future moves track = 4); `crossSlotUnique` = the no-two-members-share-this-value team rule (item: true, ability: false); `withinSlotUnique` = no-duplicate-within-a-member (only meaningful for cardinality > 1; both current tracks: false). The schema is cardinality-general now; the sampler exercises cardinality 1. **`feature_dimensions` is retired** (dropped from `meta.json` and the manifest) — anything that gated on "1 vs 2" now derives from `tracks` (species_graph gate = "has a cross-slot-unique track"; recompute's builder dispatch = "has any track"). `species_of`/`item_of` are **removed** from the schema and reconstructed as convenience arrays by both loaders (`speciesOf[i]=sites[site_of[i]]`, `itemOf[i]=track_values[i][0] ?? null`); the loaders also carry the full per-feature `track_values` so the ability track is reachable. `site_features` (per-site feature grouping) is **not stored** — it is a pure projection of `site_of` both loaders derive at load. `vocab` stays (display string, now `Species @ Item (Ability)`; drift is visible). `meta.json` also stores `type` (product tier, e.g. `"standard"`). `species_graph.json` (models with a cross-slot-unique track only) stores the precomputed species-pair interaction graph: `species: string[]` (S distinct species, alphabetical), `synergy_ut: number[]` (S*(S-1)/2 upper-triangle signed species-pair synergy, **usage-weighted** — see the `potts.py` note), `corrected_ut: number[]` (APC-corrected Frobenius norm); loaded by `sampler/model.ts:loadSpeciesGraph`, lazy-loaded in `ModelContext` alongside `teamCounts`. `manifest.json` is **schema_version 4**: a `(regulation, type)` grid, one entry per model, each tagged `regulation` + `type`, carrying per-model `tracks` and derived provenance (`V`, `n_corpus_teams`, `latest_tournament_date`). `description` lives once per type in a shared top-level `types` block (not per model); `manifest.ts` resolves it back onto each `ModelSummary`. `potts.py:load_fitted_model` and `web/src/sampler/model.ts:loadModel` both read v4 and rebuild the `(species, item)` view. `SUPPORTED_SCHEMA_VERSIONS = [4]` (both loaders + `potts.py`; no back-compat; `--recompute` rebuilds all artifacts). Ability is the first added attribute track (near-null perturbation of the fit; the model consumes only item for uniqueness this milestone, ability just makes more distinct features). The **sampler kernels (models.py batched + sampling.py/potts.ts per-chain) and the /meta hierarchical decomposition are NOT yet ability-aware** — those are separate follow-on workstreams; Stage 1 (ingest → schema v4 → both artifact loaders) is the substrate only.
- **`potts.py`** — **post-fit Potts analysis only** (no fitting/sampler change); the Potts reframe R2. Treats the fitted species+item `J` as a Potts coupling tensor: site = species, state = {absent, item…}, so the cross-species block `J[items_of_P, items_of_Q]` is that pair's Potts block relative to the absent (all-zero) reference. `load_fitted_model(model_dir)` reads a precompute artifact (v4-gated) back into a `FittedModel`, populating `track_values_of` with **every** track (item + ability) so the hierarchical decomposition can reach the ability states; the item-based fields (`item_of`, `site_index`) stay the track-0 view and the current flat-axis analysis (which treats a site's item×ability states as one alphabet) stays correct. `decompose_block` is the 2-way ANOVA / zero-sum-gauge split (species-level **synergy** = grand mean + zero-sum **item-modulation** residual). `decompose_block_hierarchical(model, P, Q)` is the **item → ability** nesting: it groups each species' states by `item_of` (track 0), collapses abilities within an item by a **usage-weighted** average → the ability-marginalized item block, runs the flat `decompose_block` on that (item synergy + zero-sum item modulation, unchanged when abilities are degenerate), and takes the **ability residual** = full block − item-level reconstruction (the ability-conditional deviation; its usage-weighted mean over abilities is zero, `cP @ residual @ cQ.T == 0`). The five item/ability pieces reconstruct the full block exactly (`HierarchicalBlockDecomposition.reconstruct()`); `synergy` is the usage-weighted full-alphabet mean (matches `species_apc_graph.synergy`). It needs no ability *labels* — grouping by item is enough, the residual absorbs whatever sub-item variation exists. `modulation_scores` is the item- **and ability-**modulation table — reports **three** magnitudes each (`mod_frob` raw Frobenius, `mod_rms` alphabet-normalized, `mod_frac` scale-free share; plus the parallel `ability_mod_*` on the residual) because they disagree and each keeps one confound: `mod_frob` ≈ pure popularity proxy (~0.9 corr), so "read against support" (`n_items`/`n_states`/`appearances`) is mandatory, not optional. `mod_*` is now item-level (ability marginalized); an **ability-degenerate** species (every item one ability, `n_states == n_items`) scores `ability_mod_* == 0` by construction (the ability analogue of `n_items == 1`). Both reduce to the pre-ability flat numbers when the model carries no ability track. `species_apc_graph` gives the plmDCA-style APC-corrected species graph (`corrected = frob − apc`) plus the signed `synergy` matrix. The graph's `synergy` is the **usage-weighted** block mean (each item-state weighted by its empirical appearance rate via `FittedModel.item_weights`, from the data marginal `m`), **not** `decompose_block`'s flat grand mean: the flat mean ranks partly by `1/alphabet_size` (dilutes many-item species whose blocks are mostly near-zero, concentrates single-item species), so the /meta §02 synergy sort is biased toward few-item Pokémon without the weighting. `frob` still uses the unweighted zero-sum gauge (standard DCA contact norm, not sorted on). `decompose_block` itself stays the unweighted ANOVA (the modulation table's canonical gauge). Gated by `tests/test_potts.py`; explored in `notebooks/potts_modulation.ipynb`.
- **`tournament_ingest.py`** — Cache schema versioned (`CACHE_VERSION`, now **4**). **Bump `CACHE_VERSION`/`_MIN_CACHE_VERSION` ONLY when the cache *structure* changes (a field added/renamed/removed, a record shape change) — never for parsing *content* changes (which teams/values are produced), and never without Kyle's explicit approval** (a content fix re-applies on his next manual re-ingest; a bump would only force an unnecessary multi-hour Limitless re-walk). Members are `(species, item, ability)` triples (`item` None for itemless, `ability` always a real string). A member missing an ability is malformed (no-ability is not a valid game state) so its whole **team is dropped** at parse time with a logged warning; likewise a member listed as a **mega forme** (`is_mega_forme` — the `Mega <Base>` prefix or a hyphen-token `-Mega-`, whole tokens only so `Meganium`/`Yanmega` pass) drops the team, since the base forme is the legal entry and the mega's ability would poison the ability vocab (base-forme-holding-a-mega-stone entries like `Absol @ Absolite (Super Luck)` are legitimate and kept). Missing nature/moves are fine. `_parse_members` returns `(members_frozenset, details_tuple)`: `Team.details` is the ordered per-member `MemberDetail` (`species, item, ability, nature, moves`) written to the cache as richer member records `[species, item, ability, nature, moves]`; `nature`/`moves` are **stored-only** (Limitless `nature` + `attacks`, in-person `badges`) so a future track needs no re-fetch, and nothing consumes them yet. Load reads the feature triple from record positions 0-2, tolerating shorter (details-less) records. `_ABILITY_ALIASES` + `normalize_name` normalize abilities (mirrors `_ITEM_ALIASES`). v4 widened the member schema for **both** sources, so `_MIN_CACHE_VERSION` is `{limitless: 4, in-person: 4}` — every pre-v4 entry is a cache miss (no upgrade path). Limitless dates are ISO timestamps, in-person dates bare `YYYY-MM-DD`; consumers must parse at day resolution.

## Conventions that span multiple files

- **`CURRENT_REGULATION`** (`constants.py` + `constants.ts`) — determines active regulation for webapp model picker; default for `--regulation` in precompute and loaders. Update when a new regulation begins.
- **Regulation relabeling** — `tournament_ingest._REGULATION_RELABELS` promotes mis-labeled Limitless events using marker species/items. Current rule covers **M-B** (start `2026-06-17`, from `{M-A, CUSTOM}`, markers Gholdengo/Metagross/Grimmsnarl + Life Orb/Light Clay). `_ILLEGAL_ITEMS_BY_REGULATION[target]` governs item-stripping for promoted events. Add marker rules when starting a new regulation Limitless hasn't tagged; remove once tagged.
- **Cross-regulation warm-start** — `prior_regulation` (loaders) / `--prior-regulation` (precompute). Assumes prior is a legality superset. Donor vocab folded in unconditionally; `_align_prior` scatters `(J, h)` onto new vocab. Features with no new data keep prior exactly; features with data relax off it. `intercept_prior_weight` (default 1.0) controls bias anchoring.
- **Regularization** — `SPECIES_LR_LAMBDA = 25.0`; `SPECIES_ITEM_LR_LAMBDA = 4.5`. Lambda is canonical L2 penalty, converted to `C = 1/lambda` internally. `meta.json` records `fit.lambda`.
- **Boltzmann fit defaults** — the `BOLTZMANN_*` constants in `constants.py` are the single source of truth for the moment-matching build recipe. Both `fit_boltzmann_ising`'s signature defaults AND precompute's `--bz-*` argparse defaults read from them, so precompute builds, notebooks, and tests that don't override a knob fit identically — tune here, not at call sites. `lr_final` defaults to `BOLTZMANN_LR_FINAL` (cosine decay **on** by default; `lr_final == lr` disables it). The heavy `fit_boltzmann_ising`-based tests in `test_boltzmann.py` / `test_potts_sampler.py` deliberately **pin lean values** (small budgets, `n_temps=2`, explicit `lr_final`) so production tuning of these constants can't perturb them; the rigorous convergence work lives in the notebooks.
- **Boltzmann learning** (`fit_boltzmann_ising`, `notebooks/boltzmann_learning.ipynb`, downstream eval in `notebooks/pl_vs_boltzmann_eval.ipynb`) — the moment-matching alternative to PL, motivated by the `pl_three_body_check` finding (the renamed, historical `three_body_check`) that PL matches conditionals not moments. On the M-A corpus it cuts the worst-feature marginal error from ~0.34 (PL over-concentration) to ~0.05. Gotchas: (1) **the model is sampled at T=1** — `estimate_moments`' cold chain (ladder index 0) MUST be at T=1 to sample `P ∝ exp(-H)`; a cold rung below 1 samples a sharper distribution (note: `pl_three_body_check`'s ladder starts at 0.5, a latent bug there — the new notebook fixes it). (2) **Reg fixes the gauge** — on the fixed-size manifold `(J,h)` is gauge-degenerate (`h→h+c·1`, `J_ij→J_ij+a_i+a_j`); the non-gauge-invariant L1/L2 penalty toward zero picks the min-norm representative, so keep `reg_lambda>0` (small for tightest moment match — larger deliberately shrinks `(J,h)`). (3) **The dominant fit error is the stochastic-gradient noise ball, killed by `lr_final`/`avg_last`** — a fixed lr orbits the optimum rather than settling, so a single final iterate is displaced most in the strong-coupling directions; the moment-reconstruction scatter then fans into a *cone* (worst-feature pair bias ~0.04, marginal ~0.11). Cosine step-decay (`lr_final≈lr/20`) **or** Polyak iterate averaging (`avg_last`) cuts that **~7×** to ~0.006, for free (same budget) — lr decay is on by default via `BOLTZMANN_LR_FINAL` (both `fit_boltzmann_ising` and precompute). This was diagnosed *not* to be regularization (a 100× λ sweep didn't move it) or mixing (more sweeps/tempering didn't fix it; 2× `n_chains` helped only via lower gradient noise). (3b) **Read `mean_resid_*`, not `max_resid_*`** in the live history — the per-iteration max is a single `n_chains`-sample snapshot, mostly Monte-Carlo noise; confirm true convergence by re-estimating the fitted model with many samples via `estimate_moments`. The PCD bank is batched across chains in pure NumPy with sparse on-bit moment accumulation (cost independent of V). Parallel tempering (`n_temps>1`) is implemented and its default lives in `BOLTZMANN_N_TEMPS` — single-T PCD sufficed on the earlier M-A corpus (not mode-trapped), so it's mainly for genuinely multimodal models. (4) **Species ensemble passes `species_of=None`** (species distinct per vocab entry → no uniqueness needed); species+item passes the real lookups + a co-occurrence `support_mask`. (5) **Species+item is sampled with the Potts move kernel by default** (`potts_moves=True`; see the `models.py` note) — separate species-swap / item-reroll moves accepting on `Z_B/Z_A`, gated by `tests/test_potts_sampler.py` (exact-moment match vs brute-force enumeration; q=2 degeneracy `log Z_B − log Z_A == −ΔH`; constraint invariants). ~40% slower per sweep than atomic swaps, matches moments identically. Pass `potts_moves=False` to force the old atomic sampler for A/B comparison. Same-species `J` is frozen at 0. This changes a species+item Boltzmann artifact's fitted numbers vs a pre-Potts atomic-swap fit (PL production path is unaffected).
- **Potts move-kernel constants** — `POTTS_REROLL_PROB` (aggregate per-sweep probability a Potts move is a track reroll vs a species swap; replaces the hardcoded `0.5` the kernels are being migrated onto) and `POTTS_TRACK_REROLL_WEIGHTS` (`{"item", "ability"}` relative weights for which track a reroll targets — item weighted far higher) in `constants.py`, mirrored in `constants.ts`. Single source of truth for the move split; tunable. `META_SUPPORT_MIN_COUNT` is the /meta drill-down display support floor (distinct from the fit-time `BOLTZMANN_SUPPORT_MIN_COUNT` coupling mask). The kernels/UI that consume these are follow-on workstreams; Stage 1 defines the constants only.
- **Sample weighting** — `RECENCY_TAU_DAYS` / `IN_PERSON_WEIGHT` in `constants.py`. Vocab cutoff requires `min_team_count` in **both** raw and weighted counts.
- **Energy formulas** — raw `H(s) = -h*s - 0.5 s'Js`. Adjusted uses `field_weight*h`. At `field_weight=0` only pairwise term remains.
- **Swap-move MH** — energy diff `dH = h_eff[out] - h_eff[in] + (J[out] - J[in]) * s + J[in, out]`. Last term corrects for swapped pair's mutual coupling.
- **Anchor-field tilt ("Anchor Strength", α)** — the completer's "build around my picks" knob, fixing the pinned-niche-mon "sore thumb" failure (a coherent 5-core with the pin as a passenger; the pairwise energy is a sum, so `P(team | pin)` is multimodal and top-1-by-frequency is seed-unstable). Samples `H_α = H − (α−1)·Σ_{p∈pins, j free} J[p,j]s_j`: an exponential tilt on the pin-integration statistic (couplings with **exactly one** pinned endpoint scaled by α; pin↔pin and free↔free untouched; `h` untouched — α is independent of `field_weight`). α=1 is the untilted conditional; `E_α[T]` is provably monotone in α. Implementation: the PT Potts kernel weights retained-member couplings per move (`site_conditional`/`siteConditional` gained optional `r_weights`, built by `_anchor_weights`/`anchorWeights` — weight α iff retained-pin XOR moving-slot-pinned, which makes a locked slot's item reroll feel the tilt too); static surfaces (meanfield, greedy, fastPath) add the equivalent `anchor_boost`/`anchorBoost` vector (`(α−1)·Σ_p J[p,·]`, zeroed on pinned sites' features) to `h_eff`. PT chain energies carry an init-time tilt correction so replica exchange targets `H_α` (gated by a JS energy-recompute invariant). **Displayed Score/Coherence stay untilted** (`teamObservables` uses raw `h`); α changes which teams are found, never their reported score. Python `parallel_tempered_mcmc`/`meanfield_marginals`/`greedy_optimize` take `anchor_strength=1.0` (feature pins only — no site pins in Python); exactness gated by `tests/test_sampling.py:TestAnchorFieldTilt` (PT vs brute-force enumeration of the tilted conditional); product validation in `notebooks/anchor_field_tilt.ipynb` (monotonicity, seed stability, raw-score/variety cost, popular-pin control on the real reg-m-a model). UI: "Anchor Strength" slider (1.0–3.0, default `DEFAULT_ANCHOR = 1`) at the top of the completer's §03 Sampler section, above the greedy toggle (visible and applied on both PT and greedy paths); share param `anc` (default-omitted, encoded even in greedy mode); part of the PT rerun fingerprint. (`field_weight` is fixed at 1 with no UI knob; `energy_discrimination.ipynb` is the research harness for it.)
- **Shareable URLs** — `render/shareLink.ts` encodes by slug (not index). Token format: `<modelSlug>.<mons>`; `<modelSlug>` is now a per-regulation slug (`reg-m-a`). Legacy tokens carried an all-digit `<fwIndex>` segment (the retired Bias Adjustment slider) between the slug and the mons — decode detects and silently drops it (slugs always contain a letter, so plain digits are unambiguous). Each mon is `speciesSlug~itemSlug~abilitySlug` (fully-locked feature pin; itemless = `~none~ability`), `speciesSlug~itemSlug` (item locked, ability free — a **partial pin**, and byte-identical to the pre-ability feature token, so legacy links decode as ability-free pins), or bare `speciesSlug` (site pin, all tracks free). The site/partial-pin token is **positional** (`sitePinSlug` encodes the pinned prefix, stopping at the first free track), so a track pinned while an earlier one is free can't be represented (not reachable from the cascading pickers). Feature mons come first in ascending index order (pre-site-pin tokens stay byte-identical); site/partial mons are appended. Completer-only default-omitting params: `x` (exclude list), `i` (include allow-list), `d` (inactive tracks), `anc` (Anchor Strength, encoded even in greedy mode since α applies to both paths), `g`/`tmp`/`a`/`seed` (`tmp` default is now T = 1.0). `LEGACY_CODE_TO_SLUG` remaps `s`/`si`/`reg-m-a-species`/`reg-m-a-species-item`/`-weighted`/the M-B olds → the unified per-regulation slug.
- **Completer roster + attribute toggle** (`/completer`, webapp-only — no Streamlit/Python mirror, no parity rows) — the completer state is an ordered `roster: RosterSlot[]` (`{site, trackValues: (string|null)[]}`, one entry per track, null = free); `components/RosterEditor.tsx` is the factored 6-slot editor (per slot: a species picker + one picker per **active track** — every active track shows its picker, including a degenerate single-value track as a one-option dropdown, so the editor is consistent across species regardless of teamsheet-contamination noise; options **cascade** to match the other pinned tracks and are **sorted by usage** = summed marginal mass, so popular items/abilities lead). Slot → pin resolution lives in `state/roster.ts`: `slotFeature` returns the **unique** feature matching every pinned track (or null when 0 or >1 match), so a slot resolves to a **feature pin** when its pins narrow the species to one feature, else a **site/partial pin** (species locked, some tracks pinned, the completer fills the free ones). `derivePins` splits a roster into `fixedIdxs` (feature pins), `fixedSites` + `sitePinTrackValues` (site/partial pins). This keeps the single-track path byte-identical (item chosen → feature pin; item free → site pin). `RosterEditor` takes `trackActive(t)` (completer: "not excluded"; analysis: all active) and is **shared with `/analysis`**, which stores its own `roster` and derives feature-level `teamIdxs` via `slotFeature` (`emptyHint={null}`; a slot missing a track is just an incomplete team member). In PT, `sampling.energy:resolveSitePins` (gained optional `sitePinTrackValues`) seeds each site pin to its best feature **matching the pinned tracks** at the front of `onNf`; `PottsContext.lockedSlots` bars species-swaps on those slots and `PottsContext.slotTrackLocks` bars rerolling a partial pin's *locked* tracks (`pottsTrackReroll` zeroes their reroll weight) while free tracks still reroll; the greedy fast path resolves a site/partial pin to that seed up front (a **point argmax** over the free tracks, not a marginal — documented). **Completion results** render as stacked cards (`completer/CompletionCard.tsx`: `CompletionCard` + `CompletionList`) showing the **full six-mon team** (pinned + filled; pinned tiles marked) in a 3-col/2-col grid with observables + actions underneath. The **attribute toggle** lives in an "Advanced options" expander as an **"Excluded attributes"** section (all attributes active by default; checking one *excludes* it): excluding track `t` clears its value on every slot (`clearTrack`), zeroes its **reroll weight** in PT (per-track, via `PTOpts.inactiveTracks` → `pt.ts`), and marginalizes it out of the distribution — the worker buckets completions by **(site, active-track values)** (`ptWorker.ts:aggregateProjected`, representative = most-frequent real feature-team; a generalization of the old species-set projection) and the UI hides that track's column (`hideItems`/`hideAbility` on `CompletionCard`). `pReroll` is forced to 0 only when **every** track is excluded (nothing to reroll). Excluding the single item track reproduces the old "species-only" behaviour exactly. The species-swap's `Z_B/Z_A` still marginalizes the degenerate track, so the species-set distribution is exact. **Known issue — species-only observables are computed on the bucket representative, and are silently misleading** (accepted; species-only is not a priority, do not "fix" it piecemeal). Only the *species-set distribution* (bucket counts / frequency) is exact. Everything else on the card is derived from that one representative feature-team, which carries concrete items the UI hides: Score/Coherence (`teamObservables`), the corpus match (`nearestObserved`), Variety (`meanPairwiseDifference` counts two reps sharing a species but not an item as differing members, inflating it) and Novelty. Three compounding reasons the representative is not trustworthy: (1) it is the modal *full* feature-team, often a small plurality of a bucket aggregated over many item combinations, so it can flip between seeds; (2) with `pReroll=0` there is no reroll move, so an item is drawn only when its species swaps *in* and then stays frozen — the within-bucket item distribution is draw-once-at-entry, not `P(items | species set)`; (3) `unique` is cleared, so the representative may hold **duplicate items** (an illegal team) and is scored and corpus-matched as such. Fixing this properly means scoring a species set as a species set (resolve each top-K bucket to a deterministic, item-legal loadout at display time, or report a marginal instead of a point estimate) — note that simply restoring `pReroll` is *not* a fix and costs species-set accuracy, since it reallocates sweeps away from species swaps toward the marginalized dimension. `/analysis` and `/meta` stay feature-level regardless of the toggle. **User-facing copy says "Pokémon", not "Species"** (the species-vs-species+item model distinction is gone). **Constraints** are two species-level multiselects: an **exclude** list (`excludedSpecies`, Pokémon that must NOT appear) and an **include** allow-list (`includedSpecies`, the only Pokémon allowed, plus pinned). The include list is **pure boundary conversion in `CompleterPage`** — it needs no sampler change: `effectiveExcludedSpecies` = every species outside `included ∪ pinned`, which flows into the existing exclude plumbing (fastPath species strings / PT feature indices). Validation: nothing on both lists, and `included + pinned ≥ 6` when the include list is non-empty (else the pool can't fill a team). Empty include list = all legal Pokémon.
- **Itemless "None" item** — a Pokémon with no held item (mainly Talonflame, for Acrobatics) is an **ordinary item value** `"None"` in the vocab, with **zero special handling** anywhere (sampler, share-links `~none`, roster editor item picker, `isStructuralPair` same-item filter). It appears only in the item picker of species that actually carry it. Technically two Pokémon can both hold no item (VGC item clause only restricts real items), so `None × None` is not a true mutual exclusion, but treating it as one keeps the code simple and the edge case is vanishingly rare in practice. The corpus's un-collapsed itemless spellings (`None`/`No item`/`Nothing`) inflate this in sparse regulations (reg-m-b) — a **deferred ingest-normalization** issue, not special-cased in the app.
- **Validation split** — chronological 90/10 (`VALIDATION_TEAM_FRAC_TEST = 0.10`). Vocab from train only; OOV test teams dropped.
- **Vocab normalization** — ingest collapses case/whitespace (`normalize_name`); mega-forme teamsheet entries are **dropped** (not collapsed to base — see `tournament_ingest.py` note). A normalizer change is a *content* change, so it does **not** warrant a `CACHE_VERSION` bump (only structural cache changes do, and only with Kyle's approval); the fix applies on the next manual re-ingest.

## Build and deploy

**Build artifacts pipeline**: ingest -> precompute per model -> generate manifest -> inspect -> commit. CI does **not** regenerate artifacts. Production identity is a `(regulation, type)` grid: one artifact per cell, slug `reg-<regulation>` for the standard tier. `type` is a **product-tier build recipe** (closed enum, today only `standard`), applied uniformly across regulations — distinct from precompute's **retired** `--type species|species_item` (feature-dimensions) meaning, which the factored schema + attribute toggle made obsolete. `PRODUCT_TYPES` / `TYPE_DESCRIPTIONS` / `TYPE_BUILDER` / `TYPE_METHOD` in `precompute.py` define each type; `model_slug(regulation, type)` derives the id. Build one model with `--build --regulation <R>` (standard implied); `--recompute` rebuilds every committed model from its stored `meta.fit` block. The `standard` recipe is a **Boltzmann** species+item+ability fit with the `BOLTZMANN_*` constants (incl. `BOLTZMANN_SUPPORT_MIN_COUNT`) — moment-matching is what makes the attribute toggle's on-the-fly track marginalization faithful. (`--recompute` now dispatches its builder off "has any track" in the stored `meta.tracks`, not the retired `feature_dimensions`.) The webapp consumes these models at their calibrated operating point `field_weight = 1`, `T = 1` (see the conventions bullet; validated by the slider-removal sweep in `pl_vs_boltzmann_eval.ipynb`).

**Domain**: `k2dex.kyletunis.com` (CNAME of `kylehtunis.github.io`). Three things must move together: `web/public/CNAME`, `VITE_BASE_PATH` in deploy workflow, `SITE_URL` in `src/siteMeta.ts`.

**SEO / prerender**: `scripts/prerender-routes.tsx` (vite-node, last step of `npm run build`) writes per-route HTML + sitemap from `src/siteMeta.ts` AND renders each route's real body content into `<div id="root">`: it shims `globalThis.fetch` to serve `/models/...` from `dist/`, loads the manifest's `default_model` through the app's own loaders, and renders the shared route tree (`src/AppRoutes.tsx`, used by both `App.tsx` and the prerender) inside `StaticRouter` + `StaticModelProvider` (a prerender-only synchronous provider exported by `ModelContext.tsx`) via `renderToPipeableStream`/`onAllReady` (so lazy article chunks resolve; redirect routes — `meta.canonical` set — keep an empty body). The client **replaces** this HTML (`createRoot`), it does not hydrate — the app's first render is model-less and could never match. `vite.config.ts` sets `ssr.noExternal` for react-router so the script and the app tree share one Router context instance. The script also stamps the model-preload `<link>`s in every page from `default_model` — the hand-written paths in `web/index.html` only matter for `npm run dev` — and injects per-route `<link rel="modulepreload">`/style-preload tags for lazy chunks (article routes) from `dist/.vite/manifest.json` (`build.manifest: true`) + `ARTICLE_SOURCES`. The mount swap is smoothed from both ends: chunks download in parallel with the main bundle, and `main.tsx` awaits the current route's lazy chunks (`ARTICLE_PRELOADS`) before `createRoot`, so prerendered article prose stays on screen until the full client render is ready. Adding a route = one entry in `siteMeta.ts`. `/meta`'s title/description carry the active regulation (`metaRouteMeta(regulation)`; the static BASE_ROUTES entry is only the model-less client fallback) so a regulation rotation updates the shipped title on the next deploy. **Species pages** (`/pokemon/<slug>`) are the exception: their `RouteMeta` is derived per model site at build time (`speciesRouteMeta` in `siteMeta.ts`) and appended to the render + sitemap loops; slugs come from `siteMeta.speciesPageSlug` (words hyphenated, ♀/♂ → f/m) — deliberately NOT the sprite slug, which collapses gendered formes — and the prerender throws on slug collisions. `usePageMeta` resolves species-page head values dynamically from the active model. No static `public/sitemap.xml`.

**SSR-safety invariant**: page/components must not touch `document`/`window` at render time (effects and handlers are fine — they never run in the prerender; the build fails loudly on violations). react-select menus use `MENU_PORTAL_TARGET` from `components/portalTarget.ts`, never a bare `document.body` prop. Heavy simulation SVGs (`SpinGrid`, `ChainStrip`, `Landscape3D`) gate their cells behind `science/widgets/useIsClient.ts` (empty same-size `<svg>` during prerender and the first client frame) so thousands of animation rects stay out of the static HTML; their markup tests mock `useIsClient` to force the client path. Prerendered numbers snapshot the committed model at build time and refresh on the next deploy.

**PT sampler** runs in a Web Worker (`completer/ptWorker.ts`).
